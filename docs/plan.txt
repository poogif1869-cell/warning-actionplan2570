# โครงการ: เว็บแจ้งเตือนผลการดำเนินงาน แผนปฏิบัติการ กยท. ปีงบประมาณ 2570

ปรับปรุงล่าสุด 27 สิงหาคม 2569

## Overview

- เว็บสำหรับ**การแจ้งเตือนผลการดำเนินงานที่ไม่เป็นไปตามเป้าหมาย**
- แจ้งเตือนโครงการในแผนปฏิบัติการประจำปีงบประมาณ 2570
- ทำงานเป็น **Next.js App Router** deploy บน **Vercel** ไม่ใช่ไฟล์ HTML เดียวแบบรุ่นก่อน

## Feature

- Login แบบง่ายด้วยรหัสตายตัว ไม่ใช้ Database
- 3 หน้า: **แจ้งเตือน** / **โครงการ** / **กรอกผล**
- กลไกแจ้งเตือน 6 กฎ พร้อมตัวเลือก "ณ เดือน" ให้เลื่อนดูสถานการณ์แต่ละเดือนได้
- ผลการดำเนินงานเก็บเป็นไฟล์ baseline ใน repo + localStorage ของแต่ละเครื่อง

## ความสามารถของเว็บ

**1. แจ้งเตือน** (หน้าแรก)
   - ตัวเลือก "ณ เดือน" 12 ปุ่ม ใช้เป็นฐานคำนวณทุกกฎ
   - ไทล์สรุป: วิกฤต / เฝ้าระวัง / โครงการที่ติดแจ้งเตือน / งบประมาณที่เกี่ยวข้อง
   - แท่งสรุปแยกตามประเภทการแจ้งเตือน
   - รายการแจ้งเตือนเรียงตามความรุนแรงแล้วตามงบ กรองตามความรุนแรง/ประเภท/ยุทธศาสตร์/หน่วยงาน/คำค้น
   - คลิกรายการเพื่อเปิดลิ้นชักรายละเอียดและกรอกผลได้ทันที
   - ตารางเกณฑ์ที่ใช้แจ้งเตือน และแถบตรวจสอบยอดกับไฟล์ต้นฉบับ

**2. โครงการ** — ตาราง 121 โครงการ (สลับเป็น 551 รายการรวมกิจกรรมได้)
   แสดงแถบเดือนแบบแกนต์ที่ระบายสีตามสถานะ: เขียว = มีแผน, เขียวเข้ม = รายงานแล้ว,
   แดง = ถึงกำหนดแต่ยังไม่รายงาน · กรองเฉพาะที่มีแจ้งเตือน/เฉพาะวิกฤตได้ · เรียงลำดับได้ทุกคอลัมน์

**3. กรอกผล** — ตัวชี้วัด 13 ตัวพร้อมคำนวณ % บรรลุและไฟจราจรทันที ·
   รายการโครงการที่ถึงกำหนดรายงานในเดือนที่เลือกแต่ยังไม่ได้กรอก ·
   ส่งออก/นำเข้าไฟล์ผล `.json` · ล้างข้อมูลในเครื่อง

**ลิ้นชักรายละเอียด** (เปิดจากหน้าไหนก็ได้) แสดงทุกฟิลด์ตามแผน, การแจ้งเตือนของโครงการนั้น,
ฟอร์มสถานะ/ความก้าวหน้า/หมายเหตุ, และ**ตารางรายงานผลรายเดือน 12 เดือน**
แต่ละเดือนกรอกได้ 3 ช่อง: ผลผลิต (Output) / ผลลัพธ์ (Outcome) / เบิกจ่าย (บาท)
วางเทียบกับค่าแผนจากไฟล์ต้นทาง

## กติกาการแจ้งเตือน

กฎทั้งหมดอยู่ใน `lib/alerts.js` เกณฑ์ตัวเลขรวมไว้ที่ค่าคงที่ `RULES` ปรับได้ที่เดียว

| ประเภท | เงื่อนไข | วิกฤต | เฝ้าระวัง |
|---|---|---|---|
| ตัวชี้วัดต่ำกว่าเป้าหมาย | เทียบผลที่รายงานกับค่าเป้าหมายปี 2570 ของตัวชี้วัด 13 ตัว | บรรลุ < 75% | บรรลุ 75–99% |
| ตัวชี้วัดยังไม่รายงานผล | ยังไม่กรอกผลตัวชี้วัด | – | ตั้งแต่ มี.ค. 70 เป็นต้นไป |
| มีแผนแต่ไม่รายงานผล | เดือนที่มีแผนและผ่านไปแล้ว แต่ไม่มีการรายงานผล | ขาด ≥ 3 เดือน | ขาด 1–2 เดือน |
| เบิกจ่ายต่ำกว่าแผน | เบิกจ่ายสะสม เทียบสัดส่วนเดือนที่มีแผนซึ่งผ่านไปแล้ว | < 60% ของที่ควรได้ | 60–85% |
| สถานะล่าช้า/ยกเลิก | ผู้รับผิดชอบระบุสถานะเอง | ล่าช้า | ยกเลิก |
| ครบกำหนดแล้วยังไม่แล้วเสร็จ | เดือนสุดท้ายที่มีแผนผ่านไปแล้ว แต่สถานะยังไม่ใช่ "แล้วเสร็จ" | ทุกกรณี | – |

หลักการที่ต้องรู้:

- กฎรายโครงการคิดที่ **ระดับโครงการ (`lvl === 1`) เท่านั้น** เพื่อไม่ให้ยอดงบซ้ำ
- **กฎ "เบิกจ่ายต่ำกว่าแผน" ประเมินเฉพาะโครงการที่รายงานผลมาแล้วอย่างน้อย 1 เดือน**
  ถ้ายังไม่รายงานเลย กฎ "มีแผนแต่ไม่รายงานผล" จับไปแล้ว ไม่เตือนซ้ำ
- **กฎ "ครบกำหนดแล้วยังไม่แล้วเสร็จ" ข้ามโครงการที่ระบุสถานะล่าช้า/ยกเลิกไว้แล้ว** ด้วยเหตุผลเดียวกัน
- **ผลที่รายงานม้วนขึ้นจากกิจกรรมลูก** (`rolledReport()` ใน `lib/alerts.js`)
  เพราะแผนรายเดือนอยู่ที่ระดับกิจกรรมเป็นส่วนใหญ่ ผู้ใช้จึงมักกรอกผลที่ระดับกิจกรรม
  ถ้าดูแต่ระดับโครงการจะเห็นเป็น "ไม่รายงานเลย" ทั้งที่รายงานแล้ว
- **ยอดเบิกจ่าย ใช้ของโครงการเองถ้ามีกรอกไว้ ไม่งั้นจึงรวมของลูก** เพื่อไม่ให้นับซ้ำสองระดับ
  ซึ่งเป็นกติกาเดียวกับที่ไฟล์ต้นฉบับใช้กับงบประมาณ

**ตัวเลือก "ณ เดือน" จำเป็น ไม่ใช่ของเล่น** — ปีงบประมาณ 2570 คือ ต.ค. 2026 ถึง ก.ย. 2027
ซึ่ง ณ วันที่เขียนยังมาไม่ถึง ถ้าผูกกับวันที่จริงอย่างเดียวหน้าแจ้งเตือนจะว่างเปล่า
โดยไม่มีคำอธิบาย จึงให้ผู้ใช้เลื่อนเดือนเองได้ ค่าเริ่มต้นคือเดือนงบประมาณปัจจุบัน
ถ้ายังไม่ถึงปีงบจะเริ่มที่ ต.ค. 69

## Login และการตั้งค่าบน Vercel

- `app/api/login/route.js` ตรวจรหัสฝั่งเซิร์ฟเวอร์ เทียบกับ `APP_USER` / `APP_PASSWORD`
  ถ้าไม่ได้ตั้ง env จะใช้ค่า `admin` / `raot4623` ที่ฝังไว้ **เพื่อให้ deploy แล้วใช้ได้ทันทีโดยไม่ต้องตั้งค่าอะไร**
- ผ่านแล้วตั้งคุกกี้ `raot_session` = `<เวลาหมดอายุ>.<HMAC-SHA256>` อายุ 8 ชั่วโมง
  เซ็นด้วย Web Crypto ซึ่งมีอยู่แล้วทั้งใน Edge runtime และ Node 18+
  **จึงไม่ต้องลงไลบรารีอย่าง jose หรือ jsonwebtoken เพิ่ม**
- `middleware.js` ตรวจลายเซ็นทุก request ยกเว้น `/login`, `/api/login` และไฟล์ static
- คุกกี้เป็น `httpOnly` + `sameSite=lax` + `secure` เมื่อ production

**ข้อจำกัดที่ต้องรู้:** วิธีนี้ทำให้รหัสผ่านไม่ติดไปกับ JS ฝั่งเบราว์เซอร์
แต่ถ้า repo เป็น public ใครอ่านซอร์สก็เห็นค่า fallback และปลอมคุกกี้ได้
ถ้าต้องการความปลอดภัยจริงจัง ให้ตั้งค่าทั้งสามตัวใน Vercel > Settings > Environment Variables:

    APP_USER        ชื่อผู้ใช้
    APP_PASSWORD    รหัสผ่าน
    AUTH_SECRET     ข้อความสุ่มยาว ๆ ใช้เซ็นคุกกี้

ตั้งแล้วต้อง Redeploy หนึ่งครั้งจึงมีผล

## วิธี deploy (ไม่ต้องติดตั้งอะไรในเครื่อง)

เครื่องนี้ไม่มี Node.js และไม่ต้องมี — Vercel จะ `npm install` และ `next build` ให้เองบนคลาวด์

```
1. git init
2. git add -A
3. git commit -m "เว็บแจ้งเตือนผลการดำเนินงาน กยท. ปีงบประมาณ 2570"
4. สร้าง repository เปล่าบน github.com
5. git remote add origin <URL ของ repo>
6. git push -u origin main
7. เข้า vercel.com > Add New > Project > Import repo นี้
8. กด Deploy ได้เลย ไม่ต้องตั้งค่าอะไรเพิ่ม (Vercel ตรวจเจอว่าเป็น Next.js เอง)
```

จะแก้อะไรทีหลังก็ commit แล้ว push — Vercel deploy ใหม่อัตโนมัติ

**ก่อน push ทุกครั้ง ให้รันสองสคริปต์นี้** เพราะรัน `next build` ในเครื่องไม่ได้:

```powershell
powershell -File check\verify-data.ps1      # ต้องผ่าน 26 ข้อ
powershell -File check\verify-imports.ps1   # ต้องไม่พบ import/export ที่ผิด
```

## วิธีรวมผลจากหลายคน (โดยไม่ต้องมี Database)

1. แต่ละคน login แล้วกรอกผลในเบราว์เซอร์ของตัวเอง (เก็บใน localStorage)
2. กด **"ส่งออกไฟล์ผล (.json)"** ในหน้ากรอกผล — ไฟล์ที่ได้รวม baseline เข้ากับสิ่งที่กรอกแล้ว
3. นำไฟล์ไปวางทับ `data/results-2570.json` แล้ว commit + push
4. Vercel deploy ใหม่ ทุกคนเห็นค่าฐานชุดใหม่ทันที

ค่าใน localStorage ของแต่ละเครื่องจะ**ทับค่าฐานเป็นรายฟิลด์** ใครที่กรอกอะไรค้างไว้จึงไม่หาย
ถ้าอยากใช้ค่าฐานล้วน ให้กด "ล้างข้อมูลในเครื่องนี้"

## ข้อตกลงเรื่องข้อมูลที่ต้องรู้

- **ระดับรายการ** ดูจากความยาวรหัสโครงการ: 6 หลัก = โครงการ, 8 หลัก = กิจกรรม, 9 หลัก = กิจกรรมย่อย
  รหัส 7 หลักในต้นฉบับ (เช่น `2010301`) ขาดเลข 0 นำหน้า สคริปต์เติมให้อัตโนมัติ
- **ห้ามบวกงบข้ามระดับ** งบของกิจกรรมย่อยรวมอยู่ในงบโครงการแม่แล้ว
  ยอดรวมต้องนับเฉพาะระดับโครงการ (`lvl === 1`) เท่านั้น
  ไม่งั้นจะได้ราว 25,500 ล้านบาทแทนที่จะเป็น 12,770 ล้านบาท
- **รหัสโครงการซ้ำกัน 9 รหัส** (553 แถว มีรหัสไม่ซ้ำ 544 รหัส) โดย 4 คู่อยู่ที่ระดับโครงการ
  และเป็นคนละโครงการจริง ๆ:
  - `010109` คาร์บอนเครดิต (60,000,000) กับ แปลงต้นแบบสวนยางปราณีต (1,443,160)
  - `020107` ทุนการศึกษาบุคลากร (6,000,000) กับ จ้างบุคลากรสนับสนุนวิจัย (27,595,700)
  - `020111` ประกวดนวัตกรรุ่นใหม่ (5,778,260) กับ ซ่อมแซมอาคารศูนย์วิจัยยาง (2,300,000)
  - `020301` จ้างที่ปรึกษาประเมินผลรัฐวิสาหกิจ (2,000,000) กับ ความร่วมมือระหว่างประเทศ (22,500,000)

  เว็บรุ่นก่อนเก็บผลติดตามด้วย `track.project[code]` **สองโครงการที่รหัสชนกันจึงใช้ข้อมูลก้อนเดียวกัน**
  รุ่นนี้จึงคีย์ด้วย `uid = code + "#" + ลำดับแถว` แทน
  ตอนนำเข้าไฟล์เก่าที่คีย์ด้วย `code` ระบบจะจับเข้ากับโครงการแรกที่พบและขึ้นเตือนให้ตรวจสอบ
- **แผนรายเดือนอยู่ที่ระดับกิจกรรมเป็นหลัก** 399/553 แถวมีธงเดือน แต่ระดับโครงการมีเองแค่ 12/121
  ต้องม้วนขึ้นด้วย `monthsOf()` เสมอ ห้ามอ่าน `item.months` ตรง ๆ
  ม้วนแล้วครอบคลุม 111 จาก 117 รหัสโครงการ
- **กิจกรรมที่เว้นช่องยุทธศาสตร์/กลยุทธ์ไว้** จะสืบทอดค่าจากโครงการแม่ตอน build
- **คอลัมน์แผนรายเดือน (ต.ค. 69 – ก.ย. 70)** ในต้นฉบับใช้ปนกันระหว่างจำนวนเงินกับจำนวนครั้ง/หน่วย
  จึงแสดงเป็นช่วงเวลาที่มีแผนเท่านั้น **ไม่นำมารวมเป็นยอดเงิน**
- **ส่วนต่าง 1.36 บาท** ยอดจากรายโครงการได้ 12,769,902,181 ขณะที่ชีต 3.1 สรุปไว้ 12,769,902,179.64
  เป็นส่วนต่างที่มีอยู่ในไฟล์ต้นฉบับเอง ไม่ใช่ความผิดพลาดของการดึงข้อมูล
- **ค่าเป้าหมายตัวชี้วัดต่างกันสองที่**: `.docx` ให้ค่าเป้าหมายรายปี 2570
  ส่วน `.xlsx` ให้ค่าสะสม เว็บใช้ `.docx` เป็นหลักและแสดงค่าสะสมกำกับไว้
- **ตัวชี้วัดทั้ง 13 ตัวเป็นแบบ "ยิ่งมากยิ่งดี" (`dir: "up"`)** โค้ดรองรับกรณี `"down"` ไว้ด้วย
  ตามสูตรเดิม แต่ข้อมูลชุดนี้ยังไม่มีตัวไหนใช้

## กับดักทางเทคนิคที่เจอมาแล้ว

**ของโปรเจกต์นี้ (Next.js)**

- **เครื่องนี้ไม่มี Node.js** จึงรัน `npm install` / `next build` / `vercel` ไม่ได้เลย
  ต้องเขียนซอร์สให้ถูกตั้งแต่ครั้งแรก เพราะจะรู้ว่าพังก็ตอน Vercel build แล้ว
  ด้วยเหตุนี้จึง **ใช้ JavaScript ไม่ใช้ TypeScript** (typecheck ในเครื่องไม่ได้)
  และ **ไม่ใส่ dependency เกินจำเป็น** — ไม่มี Tailwind ไม่มี chart library ไม่มี auth library
- **`useSearchParams()` ใน Next 14 ต้องครอบ Suspense** ไม่งั้น build ไม่ผ่าน
  หน้า login จึงอ่าน `window.location.search` ตอนกดส่งแทน
- **อย่าอ่าน `localStorage` ตอน render แรก** ผลฝั่งเซิร์ฟเวอร์กับเบราว์เซอร์จะไม่ตรงกัน
  แล้ว React จะเตือน hydration — ต้องอ่านใน `useEffect` เท่านั้น
  ด้วยเหตุผลเดียวกัน ค่าเริ่มต้นของ "ณ เดือน" ต้องเป็นค่าคงที่ก่อน แล้วค่อยแก้ใน effect
- **`localStorage.getItem()` คืน `null` เมื่อไม่มีค่า และ `Number(null)` เป็น `0`**
  ถ้าเช็คแค่ช่วง 0–11 จะได้ ต.ค. 69 เสมอ ต้องกันกรณี `null` แยกต่างหาก
- **ทุกการเรียก `localStorage` ต้องครอบ try/catch** และมีทางลงเมื่อเขียนไม่ได้ (แถบเตือน + ส่งออกไฟล์เอง)
- **กราฟแท่งห้ามใช้ SVG + `preserveAspectRatio="none"`** ตัวอักษรไทยจะถูกยืดตามความกว้างจอ
  ใช้ `<div>` + CSS width เป็น % แทน
- **ฟอนต์ไทยห้ามลิงก์ออนไลน์** ใช้สแตก `'Sarabun','Noto Sans Thai','Leelawadee UI',Tahoma`
  (สองตัวหลังติดมากับ Windows)

**ของ PowerShell (สคริปต์ใน check\)**

- **`$s` กับ `$S` เป็นตัวแปรเดียวกัน** PowerShell ไม่สนตัวพิมพ์เล็กใหญ่
  เคยตั้ง `$s = 0` แล้วทับ string table `$S` จนอ่านข้อมูลผิดทั้งสคริปต์
- **ไฟล์ .ps1 ที่มีภาษาไทยต้องมี BOM** ไม่งั้น PowerShell 5.1 อ่านเป็น ANSI แล้วตัวอักษรเพี้ยน
- **backtick ใน double quote คือตัว escape** เขียน `"``"` ไม่ได้ ต้องใช้ `[char]96`
- ไม่มี `&&` / `||` — ใช้ `A; if ($?) { B }` · ไม่มี ternary, `??`, `?.`
- **อย่า redirect stderr ของ .exe** (`2>$null`) จะกลายเป็น NativeCommandError แม้ exit code = 0
- `-replace` เป็น regex — แทนที่สตริงที่มี `*` `(` `)` ให้ใช้ `.Replace()`

**ของโปรเจกต์เดิม (`Desktop\Gif`) — ยังใช้ได้ถ้าต้องแตก Excel ใหม่**

- **อ่าน sharedStrings.xml ของ .xlsx** ห้ามใช้ `XmlReader.ReadElementContentAsString()`
  เพราะมันเลื่อน reader ข้าม `EndElement` ทำให้ `<si>` ถูกยุบรวมกัน (ได้ 33 จาก 4,354 รายการ)
  ต้องใช้ `XmlDocument` + XPath แทน
- **PowerShell 5.1**: `si` เป็น alias ของ `Set-Item` ห้ามตั้งชื่อฟังก์ชันว่า `SI`
- **แทนที่ marker `/*__PLAN_DATA__*/`** ต้องใช้ `.Replace()` ไม่ใช่ `-replace`
- **JSON ที่ฝังใน `<script>`** ต้องแปลง `<` เป็น `&lt;` กัน `</script>` ในข้อมูลปิดบล็อกก่อนเวลา
