# โครงการ: เว็บแจ้งเตือนผลการดำเนินงาน แผนปฏิบัติการ กยท. ปีงบประมาณ 2570

ปรับปรุงล่าสุด 29 สิงหาคม 2569

## Overview

- เว็บสำหรับ**การแจ้งเตือนผลการดำเนินงานที่ไม่เป็นไปตามเป้าหมาย**
- แจ้งเตือนโครงการในแผนปฏิบัติการประจำปีงบประมาณ 2570
- ทำงานเป็น **Next.js App Router** deploy บน **Vercel** ไม่ใช่ไฟล์ HTML เดียวแบบรุ่นก่อน

## Feature

- Login ด้วย **Supabase Auth** (อีเมล + รหัสผ่าน) ไม่มีหน้าสมัครสมาชิก
- 7 หน้า: **ภาพรวม** / **แจ้งเตือน** / **ยุทธศาสตร์&ตัวชี้วัด** / **โครงการ** / **งบประมาณ** / **ความเชื่อมโยงแผน** / **ความเสี่ยง**
- กลไกแจ้งเตือน 8 กฎ พร้อมตัวเลือก "ณ เดือน" ให้เลื่อนดูสถานการณ์แต่ละเดือนได้
- ผลการดำเนินงานเก็บใน **Supabase** ทุกคนที่เข้าสู่ระบบเห็นข้อมูลชุดเดียวกันทันที

## บัญชีผู้ใช้

**ไม่มีรหัสตายตัวแล้ว** ระบบเดิม (`admin` / `raot4623`) ถูกถอดออกทั้งหมดเมื่อ 28 ส.ค. 2569
พร้อมกับไฟล์ `lib/auth.js`, `app/api/login/`, `app/api/logout/`

ผู้ใช้ถูกสร้างจากหน้า Supabase เท่านั้น: **Authentication > Users > Add user**
ใส่อีเมลกับรหัสผ่าน แล้ว**ติ๊ก "Auto Confirm User"** ไม่งั้นจะเข้าไม่ได้จนกว่าจะยืนยันอีเมล

**ต้องปิดการสมัครสมาชิกเองด้วย**: Authentication > Sign In / Providers > Email
ปิด "Allow new users to sign up" — เว็บไม่มีหน้าสมัครอยู่แล้ว แต่ถ้าไม่ปิดตรงนี้
ใครก็ยิง API สมัครเองได้ เพราะ anon key เป็นของสาธารณะโดยธรรมชาติ

## เป้าหมาย

รวมข้อมูลแผนปฏิบัติการที่กระจายอยู่ใน Excel หลายชีตและ Word ให้มาอยู่ในเว็บเดียว
แล้วต่อยอดเป็น**ระบบเฝ้าระวัง** ที่ชี้ให้เห็นทันทีว่าโครงการไหนกำลังหลุดเป้า
ตัวชี้วัดตัวไหนยังไม่บรรลุ และเดือนไหนมีแผนแต่ไม่มีใครรายงานผล

## ความสามารถของเว็บ

7 หน้า ทุกหน้าใช้ตัวเลือก "ณ เดือน" ร่วมกัน (เก็บใน localStorage ของแต่ละเครื่อง)

**1. ภาพรวม** (`/` หน้าแรก) — แถบสถานะการแจ้งเตือน · งบประมาณตามแผน 4 ก้อน ·
   งบตามยุทธศาสตร์ · ตารางเพดานงบตามแหล่งเงินเทียบกับที่จัดสรรจริง (พร้อมแถบสัดส่วน
   และเตือนเป็นสีแดงเมื่อจัดสรรเกินเพดาน) · งบตามแผนงาน · 10 หน่วยงานที่ถืองบสูงสุด ·
   เครื่องมือสำรอง/นำเข้าข้อมูล · แถบตรวจสอบยอดกับไฟล์ต้นฉบับ

**2. แจ้งเตือน** (`/alerts`) — ไทล์สรุปวิกฤต/เฝ้าระวัง · แท่งแยกตามประเภท ·
   รายการแจ้งเตือนเรียงตามความรุนแรงแล้วตามงบ กรองตามความรุนแรง/ประเภท/ยุทธศาสตร์/
   หน่วยงาน/คำค้น · ตารางเกณฑ์ที่ใช้แจ้งเตือนทั้งหมด
   จำนวน "วิกฤต" แสดงเป็นป้ายแดงบนเมนูตลอดเวลา

**3. ยุทธศาสตร์ & ตัวชี้วัด** (`/strategy`) — สรุปการบรรลุตัวชี้วัดองค์กร ·
   งบตามยุทธศาสตร์ · แยกรายยุทธศาสตร์ให้ตารางกลยุทธ์กับตัวชี้วัดที่สังกัดอยู่ด้วยกัน
   กรอกผลตัวชี้วัดได้ตรงนั้น คำนวณ % บรรลุและไฟจราจรทันที

**4. โครงการ/กิจกรรม** (`/projects`) — ตาราง 121 โครงการ (สลับเป็น 551 รายการรวมกิจกรรมได้)
   - คอลัมน์ **ตัวชี้วัดผลผลิต/ผลลัพธ์** แสดงค่าตามแผนคู่กับผลที่รายงานล่าสุด
   - คอลัมน์ **เบิกจ่าย** ดึงมาจากรายงานงบประมาณโครงการ
   - แถบเดือนแบบแกนต์: เขียว = มีแผน, เขียวเข้ม = รายงานแล้ว, แดง = ถึงกำหนดแต่ยังไม่รายงาน
   - กรองเฉพาะที่มีแจ้งเตือน/เฉพาะวิกฤตได้ · เรียงลำดับได้ทุกคอลัมน์

**5. งบประมาณโครงการ** (`/budget`) — ยอดรวม · ยอดแยกตามหมวดค่าใช้จ่าย 4 หมวด ·
   ยอดเบิกจ่ายรายเดือนทั้งแผน · ตารางรายโครงการพร้อมงบตามแผน/เบิกจ่าย/คงเหลือ
   กราฟโดนัทเลือกมุมมองได้ · กด "รายงานงบประมาณ" เพื่อเพิ่ม/แก้รายการ · ปุ่ม PDF ต่อโครงการ

**6. ความเชื่อมโยงแผน** (`/linkage`) — **เลือกได้ว่าจะดูแผนไหน** 4 แผน
   (ยุทธศาสตร์ชาติ / แผนแม่บทฯ / แผนปฏิบัติราชการ กษ. / แผนวิสาหกิจ กยท.)
   แล้วเลือกชั้นภายในแผนนั้นอีกที · บอกด้วยว่ามีกี่โครงการที่ยังไม่ระบุการเชื่อมโยงในชั้นนั้น
   คลิกจำนวนโครงการเพื่อกางดูรายชื่อ

**7. ความเสี่ยง** (`/risk`) — **แดชบอร์ดสรุปการแจ้งเตือนความเสี่ยง** ·
   จำนวนโครงการแยกตามระดับความเสี่ยงที่รายงาน · รายการแจ้งเตือนความเสี่ยง ·
   ตารางทะเบียนความเสี่ยงจากไฟล์แผนพร้อมช่อง**รายงานความเสี่ยงรายเดือน**
   (ระดับ / สถานการณ์ / มาตรการ) กรอกได้ในตารางเลย

**ลิ้นชักรายละเอียด** (เปิดจากหน้าไหนก็ได้) แบ่ง 3 แท็บ:
- *รายงานผลรายเดือน* — สถานะ/ความก้าวหน้า/หมายเหตุ · ตัวชี้วัดความสำเร็จตามแผน ·
  ตาราง 12 เดือน กรอกผลผลิต (Output) และผลลัพธ์ (Outcome)
  ส่วนเบิกจ่ายกดเพื่อกางรายการงบประมาณของเดือนนั้นมาแก้ได้ทันที
- *ความเสี่ยง* — ทะเบียนความเสี่ยงตามแผน + คะแนนควบคุมภายใน และตารางรายงานรายเดือน 12 เดือน
- *รายละเอียดตามแผน* — ทุกฟิลด์ · ความเชื่อมโยงแผน · กิจกรรมลูก · ปุ่มล้างข้อมูลของโครงการนี้

## รายงานงบประมาณโครงการ

หนึ่งโครงการมีรายการงบประมาณได้**หลายรายการต่อเดือน** (เช่น เดินทางหลายครั้ง)
แต่ละรายการมีวันที่ รายละเอียด และค่าใช้จ่าย **4 หมวด**:

    ค่าเบี้ยเลี้ยง · ค่าที่พัก · ค่าเดินทาง · ค่าน้ำมันเชื้อเพลิง

### บันทึกได้ทั้งระดับโครงการและระดับกิจกรรม

กดปุ่ม **"รายงานงบประมาณ"** ที่แถวโครงการ จะกางฟอร์มออกมาสองส่วน:
ระดับโครงการ และระดับกิจกรรมทีละกิจกรรม

**ยอดของโครงการ = รายการของตัวเอง + รายการของกิจกรรมลูกทุกชั้น** (`budgetRollup()` ใน `lib/store.jsx`)

ข้อนี้**ต่างจากงบตามแผน** ซึ่งห้ามบวกข้ามระดับ เพราะงบตามแผนของกิจกรรม
รวมอยู่ในงบโครงการแม่มาแต่ต้น ส่วนงบที่ใช้จริงเป็นสิ่งที่ผู้ใช้กรอกเอง จะกรอกที่ระดับไหนก็ได้
ถ้าไม่บวกทุกระดับ เงินที่กรอกไว้ที่กิจกรรมจะหายไปจากยอดโครงการ

⚠️ **อย่ากรอกยอดเดียวกันซ้ำทั้งสองระดับ จะกลายเป็นนับซ้ำ**
(`rolledReport()` ใน `lib/alerts.js` ใช้กติกาเดียวกัน ตัวเลขทั้งเว็บจึงตรงกัน)

### ล็อกรายการที่บันทึกแล้ว

- เพิ่มรายการ → กรอก (บันทึกร่างอัตโนมัติทุก 0.8 วินาที) → กด **"บันทึกรายงาน"** → ล็อก
- รายการที่ล็อกแล้วพิมพ์ไม่ได้ ต้องกด **"แก้ไข"** ที่แถวนั้นก่อน (หรือ "แก้ไขทั้งหมด")
- จุดสีเขียว = บันทึกแล้ว · จุดสีเหลือง = ยังไม่บันทึก
- เก็บสถานะที่คอลัมน์ `budget_entries.saved`

### ยอดเบิกจ่ายรายเดือนเป็นค่าที่คำนวณมา

**ไม่ใช่ค่าที่กรอกมือ** มาจากผลรวมของรายการงบประมาณในเดือนนั้น
ทำให้รายงานงบประมาณกับรายงานผลรายเดือนเป็นตัวเลขเดียวกันเสมอ
และกฎแจ้งเตือน "เบิกจ่ายต่ำกว่าแผน" ใช้ยอดเดียวกันนี้

คอลัมน์ `monthly_reports.spend` ยังอยู่ในฐานข้อมูลเพื่อไม่ให้ยอดที่เคยกรอกมือไว้หาย
จะถูกใช้ก็ต่อเมื่อเดือนนั้นยังไม่มีรายการงบประมาณเลย (แสดงเป็น "ยอดเดิม")

### กราฟโดนัท 3 มุมมอง

เลือกได้ว่าจะดูสัดส่วนยอดเบิกจ่ายแบบไหน: **รายเดือน / ตามแหล่งงบประมาณ / ตามยุทธศาสตร์**

โดนัทเขียนด้วย SVG วงกลม + `stroke-dasharray` โดย**ไม่มีตัวอักษรอยู่ใน SVG เลย**
ป้ายชื่อทั้งหมดอยู่ในตาราง HTML ข้าง ๆ จึงไม่ติดกับดักตัวอักษรไทยถูกยืด

### ส่งออกเป็น PDF

ปุ่ม **PDF** ที่แถวโครงการ เปิดกล่องพิมพ์ของเบราว์เซอร์ แล้วเลือก "Save as PDF"

**ไม่ใช้ไลบรารี PDF เลย** เพราะเครื่องที่พัฒนาไม่มี Node.js จึงเพิ่ม dependency ไม่ได้
และวิธีนี้ได้ฟอนต์ไทยถูกต้องเสมอโดยไม่ต้องฝังฟอนต์ลงไฟล์ PDF เอง

รายงานประกอบด้วย: ชื่อโครงการและข้อมูลหัวเรื่อง · **งบที่ได้รับจัดสรรตามแผนปฏิบัติการ /
งบที่ใช้ไป / งบคงเหลือ** · ยอดแยก 4 หมวด · **ตารางกิจกรรม**พร้อมงบตามแผน-ใช้ไป-คงเหลือ ·
ยอดรายเดือน 12 เดือน · รายละเอียดรายการเบิกจ่ายทุกรายการ

DOM ของรายงานถูก render ก่อนเรียก `window.print()` เสมอ และมีคลาส `body.printing-report`
คุมการซ่อน/แสดง — ถ้าไม่มีคลาสนี้ การกด Ctrl+P เองจะพิมพ์หน้าเว็บตามปกติ
ไม่ใช่ได้กระดาษเปล่า (เป็นกับดักที่เจอมาแล้วในเว็บรุ่นก่อน)

กฎทั้งหมดอยู่ใน `lib/alerts.js` เกณฑ์ตัวเลขรวมไว้ที่ค่าคงที่ `RULES` ปรับได้ที่เดียว

| ประเภท | เงื่อนไข | วิกฤต | เฝ้าระวัง |
|---|---|---|---|

| เบิกจ่ายต่ำกว่าแผน | เบิกจ่ายสะสม เทียบสัดส่วนเดือนที่มีแผนซึ่งผ่านไปแล้ว | < 60% ของที่ควรได้ | 60–85% |
| สถานะล่าช้า/ยกเลิก | ผู้รับผิดชอบระบุสถานะเอง | ล่าช้า | ยกเลิก |
| ครบกำหนดแล้วยังไม่แล้วเสร็จ | เดือนสุดท้ายที่มีแผนผ่านไปแล้ว แต่สถานะยังไม่ใช่ "แล้วเสร็จ" | ทุกกรณี | – |
| ความเสี่ยงระดับสูง | ระดับความเสี่ยงที่รายงานล่าสุด (ไม่เกินเดือนที่เลือก) | สูงมาก | สูง |
| ยังไม่รายงานความเสี่ยง | อยู่ในทะเบียนความเสี่ยงตามไฟล์แผน แต่ยังไม่เคยรายงานเลย | – | ตั้งแต่เดือนที่ 3 |

หลักการที่ต้องรู้:

- กฎรายโครงการคิดที่ **ระดับโครงการ (`lvl === 1`) เท่านั้น** เพื่อไม่ให้ยอดงบซ้ำ
- **กฎ "เบิกจ่ายต่ำกว่าแผน" ประเมินเฉพาะโครงการที่รายงานผลมาแล้วอย่างน้อย 1 เดือน**
  ถ้ายังไม่รายงานเลย กฎ "มีแผนแต่ไม่รายงานผล" จับไปแล้ว ไม่เตือนซ้ำ
- **กฎ "ครบกำหนดแล้วยังไม่แล้วเสร็จ" ข้ามโครงการที่ระบุสถานะล่าช้า/ยกเลิกไว้แล้ว** ด้วยเหตุผลเดียวกัน
- **กฎ "ความเสี่ยงระดับสูง" ดูรายงานล่าสุดที่ไม่เกินเดือนที่เลือก ไม่ใช่ทุกเดือนที่เคยรายงาน**
  เพราะความเสี่ยงเดือนเก่าที่แก้ไปแล้วไม่ควรค้างเตือน ถ้าเดือนหลังรายงานว่าลดระดับลงแล้ว
- **ผลที่รายงานม้วนขึ้นจากกิจกรรมลูก** (`rolledReport()` ใน `lib/alerts.js`)
  เพราะแผนรายเดือนอยู่ที่ระดับกิจกรรมเป็นส่วนใหญ่ ผู้ใช้จึงมักกรอกผลที่ระดับกิจกรรม
  ถ้าดูแต่ระดับโครงการจะเห็นเป็น "ไม่รายงานเลย" ทั้งที่รายงานแล้ว
- **ยอดเบิกจ่าย ใช้ของโครงการเองถ้ามีกรอกไว้ ไม่งั้นจึงรวมของลูก** เพื่อไม่ให้นับซ้ำสองระดับ
  ซึ่งเป็นกติกาเดียวกับที่ไฟล์ต้นฉบับใช้กับงบประมาณ

**ตัวเลือก "ณ เดือน" จำเป็น ไม่ใช่ของเล่น** — ปีงบประมาณ 2570 คือ ต.ค. 2026 ถึง ก.ย. 2027
ซึ่ง ณ วันที่เขียนยังมาไม่ถึง ถ้าผูกกับวันที่จริงอย่างเดียวหน้าแจ้งเตือนจะว่างเปล่า
โดยไม่มีคำอธิบาย จึงให้ผู้ใช้เลื่อนเดือนเองได้ ค่าเริ่มต้นคือเดือนงบประมาณปัจจุบัน
ถ้ายังไม่ถึงปีงบจะเริ่มที่ ต.ค. 69

## Supabase: Login และฐานข้อมูล

### สิ่งที่ต้องตั้งค่า

env สองตัว ใช้ทั้งฝั่งเบราว์เซอร์และ middleware:

    NEXT_PUBLIC_SUPABASE_URL        Project URL
    NEXT_PUBLIC_SUPABASE_ANON_KEY   anon public key

ทั้งคู่อยู่ที่ Supabase > Project Settings > Data API
บน Vercel ใส่ที่ Settings > Environment Variables แล้ว **Redeploy หนึ่งครั้ง**
รันในเครื่องให้คัดลอก `.env.local.example` เป็น `.env.local`

ถ้ายังตั้งไม่ครบ middleware จะพาไปหน้า `/setup` ที่บอกวิธีตั้งค่าเป็นขั้นตอน
แทนที่จะปล่อยให้เว็บพังเงียบ ๆ

### anon key เปิดเผยได้ ความปลอดภัยอยู่ที่ RLS

anon key ถูกฝังลงบันเดิลที่ส่งให้เบราว์เซอร์อยู่แล้วโดยการออกแบบของ Supabase
**การซ่อนคีย์ไม่ใช่มาตรการความปลอดภัย** สิ่งที่กันจริงคือ Row Level Security ใน
`supabase/schema.sql` ซึ่งอนุญาตเฉพาะ role `authenticated` เท่านั้นที่อ่าน/เขียนได้
ส่วน `anon` (ยังไม่ล็อกอิน) ทำอะไรไม่ได้เลย

ห้ามเอา **service_role key** มาใส่ใน `NEXT_PUBLIC_*` เด็ดขาด — คีย์นั้นข้าม RLS ทั้งหมด

### การไหลของเซสชัน

- `app/login/page.jsx` เรียก `supabase.auth.signInWithPassword()` ฝั่งเบราว์เซอร์
- `@supabase/ssr` เก็บ token ลงคุกกี้ ทำให้ middleware อ่านต่อได้
- `middleware.js` เรียก `supabase.auth.getUser()` ทุก request
  **ต้องเป็น `getUser()` ไม่ใช่ `getSession()`** เพราะ `getSession()` อ่านคุกกี้ตรง ๆ
  โดยไม่ตรวจกับเซิร์ฟเวอร์ จึงปลอมได้
- middleware ยังต่ออายุ token ให้ด้วย จึง**ต้องคืน response ตัวที่ `setAll` เขียนคุกกี้ลงไป**
  ถ้าคืน `NextResponse.next()` ตัวใหม่ token ที่รีเฟรชแล้วจะไม่ถึงเบราว์เซอร์
  แล้วผู้ใช้จะหลุดล็อกอินเป็นระยะโดยหาสาเหตุไม่เจอ

### ตารางในฐานข้อมูล

รัน `supabase/schema.sql` ใน SQL Editor ของ Supabase (รันซ้ำได้ ไม่ลบข้อมูลเดิม)

| ตาราง | เก็บอะไร | คีย์ |
|---|---|---|
| `kpi_results` | ผลตัวชี้วัด 13 ตัว | `no` |
| `project_results` | สถานะ/ความก้าวหน้า/หมายเหตุ รายโครงการ | `uid` |
| `monthly_reports` | ผลผลิต/ผลลัพธ์/ปัญหาอุปสรรค/วิธีแก้ รายเดือน | `(uid, month)` |
| `budget_entries` | รายการเบิกจ่าย แยก 4 หมวด หลายรายการต่อเดือนได้ + สถานะ `saved` | `id` (uuid) |
| `risk_reports` | ระดับ/สถานการณ์/มาตรการ ความเสี่ยงรายเดือน | `(uid, month)` |

`budget_entries` ใช้ `id` เป็นคีย์ ไม่ใช่ `(uid, month)` เพราะหนึ่งเดือนมีได้หลายรายการ

**ผลรายเดือนแยกเป็นตารางต่างหาก ไม่ยัดเป็น jsonb ก้อนเดียว** เพื่อให้สองคน
แก้คนละเดือนของโครงการเดียวกันพร้อมกันแล้วไม่เขียนทับกัน

**คีย์เป็น `uid` ไม่ใช่รหัสโครงการ** เพราะไฟล์แผนมีรหัสซ้ำ 9 รหัส (ดูหัวข้อข้อตกลงเรื่องข้อมูล)

ข้อมูลแผนเอง (553 รายการ) ไม่ได้อยู่ในฐานข้อมูล ยังฝังไปกับเว็บใน `data/plan-data.json`
เพราะเป็นข้อมูลนิ่งที่ไม่มีใครแก้ ทำให้หน้าเว็บ render ได้โดยไม่ต้องรอ query

### การบันทึก

`lib/store.jsx` บันทึกแบบ optimistic — อัปเดตหน้าจอทันที แล้วค่อย upsert ขึ้น Supabase
หลังหยุดพิมพ์ 800 ms เพื่อไม่ให้ยิง request ทุกตัวอักษร
ถ้าบันทึกไม่สำเร็จจะขึ้นแถบแดงและข้อมูลบนจอยังอยู่ กดปุ่ม "บันทึกเดี๋ยวนี้" ในหน้ากรอกผลซ้ำได้

## วิธี deploy (ไม่ต้องติดตั้งอะไรในเครื่อง)

เครื่องนี้ไม่มี Node.js และไม่ต้องมี — Vercel จะ `npm install` และ `next build` ให้เองบนคลาวด์

repo: **github.com/poogif1869-cell/warning-actionplan2570** (push ครั้งแรกแล้วเมื่อ 27 ส.ค. 2569)

```
1. git init
2. git add -A                     <-- ต้องเป็น -A ไม่ใช่ add README.md อย่างเดียว
3. git commit -m "first commit"
4. git branch -M main
5. git remote add origin ssh://git@ssh.github.com:443/poogif1869-cell/warning-actionplan2570.git
6. git push -u origin main
7. เข้า vercel.com > Add New > Project > Import repo นี้
8. กด Deploy ได้เลย ไม่ต้องตั้งค่าอะไรเพิ่ม (Vercel ตรวจเจอว่าเป็น Next.js เอง)
```

**เครือข่ายนี้บล็อก SSH port 22** — ใช้ `git@github.com:...` ตามที่ GitHub แนะนำจะค้างแล้ว
ขึ้น `Connection timed out` ต้องใช้ port 443 ผ่านโฮสต์ `ssh.github.com` แทน (ข้อ 5 ข้างบน)
ถ้าอยากให้ใช้ `git@github.com:` ได้ทุก repo ให้ใส่ใน `~/.ssh/config`:

```
Host github.com
  HostName ssh.github.com
  Port 443
  User git
```

ทดสอบว่าต่อได้ไหมด้วย `ssh -T -p 443 git@ssh.github.com` — ถ้าขึ้น
"Hi <ชื่อผู้ใช้>! You've successfully authenticated" แปลว่าใช้ได้ (exit code เป็น 1 ถือว่าปกติ)

จะแก้อะไรทีหลังก็ commit แล้ว push — Vercel deploy ใหม่อัตโนมัติ

**ก่อน push ทุกครั้ง ให้รันสองสคริปต์นี้** เพราะรัน `next build` ในเครื่องไม่ได้:

## การใช้งานร่วมกันหลายคน

ทุกคนที่เข้าสู่ระบบเห็นและแก้ข้อมูลชุดเดียวกันในฐานข้อมูลเดียวกัน กรอกแล้วบันทึกเอง

  (ยังไม่ได้ทำ realtime อัปเดตอัตโนมัติ)

- **"นำเข้าไฟล์สำรอง"** จะ**เขียนทับ**แถวที่คีย์ตรงกันในฐานข้อมูล และทุกคนเห็นผลทันที
  ใช้เฉพาะตอนกู้คืนข้อมูลเท่านั้น

ตอนนี้ทุกคนที่ล็อกอินมีสิทธิ์เท่ากันหมด (แก้ได้ทุกโครงการ) ถ้าต้องการจำกัดให้แก้ได้
เฉพาะของหน่วยงานตัวเอง ต้องเพิ่มตาราง `profiles` แล้วแก้เงื่อนไข `using(...)`
ใน `supabase/schema.sql`

## ข้อตกลงเรื่องข้อมูลที่ต้องรู้

- **ระดับรายการ** ดูจากความยาวรหัสโครงการ: 6 หลัก = โครงการ, 8 หลัก = กิจกรรม, 9 หลัก = กิจกรรมย่อย
  รหัส 7 หลักในต้นฉบับ (เช่น `2010301`) ขาดเลข 0 นำหน้า สคริปต์เติมให้อัตโนมัติ
- **ห้ามบวกงบข้ามระดับ** งบของกิจกรรมย่อยรวมอยู่ในงบโครงการแม่แล้ว
  ยอดรวมต้องนับเฉพาะระดับโครงการ (`lvl === 1`) เท่านั้น
  ไม่งั้นจะได้ราว 25,500 ล้านบาทแทนที่จะเป็น 12,770 ล้านบาท
- **รหัสโครงการซ้ำกัน 9 รหัส** (553 แถว มีรหัสไม่ซ้ำ 544 รหัส) โดย 4 คู่อยู่ที่ระดับโครงการ
  และเป็นคนละโครงการจริง ๆ:
  - `010109` คาร์บอนเครดิต (60,000,000) กับ แปลงต้นแบบสวนยางปราณีต (1,443,160)
  - `020107` ทุนการศึกษาบุคลากร (6,000,000) กับ จ้างบุคลากรสนับสนุนวิจัย (27,595,700)
  - `020111` ประกวดนวัตกรรุ่นใหม่ (5,778,260) กับ ซ่อมแซมอาคารศูนย์วิจัยยาง (2,300,000)
  - `020301` จ้างที่ปรึกษาประเมินผลรัฐวิสาหกิจ (2,000,000) กับ ความร่วมมือระหว่างประเทศ (22,500,000)

  เว็บรุ่นก่อนเก็บผลติดตามด้วย `track.project[code]` **สองโครงการที่รหัสชนกันจึงใช้ข้อมูลก้อนเดียวกัน**
  รุ่นนี้จึงคีย์ด้วย `uid = code + "#" + ลำดับแถว` แทน
  ตอนนำเข้าไฟล์เก่าที่คีย์ด้วย `code` ระบบจะจับเข้ากับโครงการแรกที่พบและขึ้นเตือนให้ตรวจสอบ
- **แผนรายเดือนอยู่ที่ระดับกิจกรรมเป็นหลัก** 399/553 แถวมีธงเดือน แต่ระดับโครงการมีเองแค่ 12/121
  ต้องม้วนขึ้นด้วย `monthsOf()` เสมอ ห้ามอ่าน `item.months` ตรง ๆ
  ม้วนแล้วครอบคลุม 111 จาก 117 รหัสโครงการ
- **กิจกรรมที่เว้นช่องยุทธศาสตร์/กลยุทธ์ไว้** จะสืบทอดค่าจากโครงการแม่ตอน build
- **คอลัมน์แผนรายเดือน (ต.ค. 69 – ก.ย. 70)** ในต้นฉบับใช้ปนกันระหว่างจำนวนเงินกับจำนวนครั้ง/หน่วย
  จึงแสดงเป็นช่วงเวลาที่มีแผนเท่านั้น **ไม่นำมารวมเป็นยอดเงิน**
- **ส่วนต่าง 1.36 บาท** ยอดจากรายโครงการได้ 12,769,902,181 ขณะที่ชีต 3.1 สรุปไว้ 12,769,902,179.64
  เป็นส่วนต่างที่มีอยู่ในไฟล์ต้นฉบับเอง ไม่ใช่ความผิดพลาดของการดึงข้อมูล
- **ค่าเป้าหมายตัวชี้วัดต่างกันสองที่**: `.docx` ให้ค่าเป้าหมายรายปี 2570
  ส่วน `.xlsx` ให้ค่าสะสม เว็บใช้ `.docx` เป็นหลักและแสดงค่าสะสมกำกับไว้
- **ตัวชี้วัดทั้ง 13 ตัวเป็นแบบ "ยิ่งมากยิ่งดี" (`dir: "up"`)** โค้ดรองรับกรณี `"down"` ไว้ด้วย
  ตามสูตรเดิม แต่ข้อมูลชุดนี้ยังไม่มีตัวไหนใช้

## กับดักทางเทคนิคที่เจอมาแล้ว

**ของโปรเจกต์นี้ (Next.js)**

- **เครื่องนี้ไม่มี Node.js** จึงรัน `npm install` / `next build` / `vercel` ไม่ได้เลย
  ต้องเขียนซอร์สให้ถูกตั้งแต่ครั้งแรก เพราะจะรู้ว่าพังก็ตอน Vercel build แล้ว
  ด้วยเหตุนี้จึง **ใช้ JavaScript ไม่ใช้ TypeScript** (typecheck ในเครื่องไม่ได้)
  และ **ไม่ใส่ dependency เกินจำเป็น** — ไม่มี Tailwind ไม่มี chart library
  (มีแค่ `@supabase/ssr` กับ `@supabase/supabase-js` ซึ่งจำเป็นจริง ๆ)
- **`useSearchParams()` ใน Next 14 ต้องครอบ Suspense** ไม่งั้น build ไม่ผ่าน
  หน้า login จึงอ่าน `window.location.search` ตอนกดส่งแทน
- **อย่าอ่าน `localStorage` ตอน render แรก** ผลฝั่งเซิร์ฟเวอร์กับเบราว์เซอร์จะไม่ตรงกัน
  แล้ว React จะเตือน hydration — ต้องอ่านใน `useEffect` เท่านั้น
  ด้วยเหตุผลเดียวกัน ค่าเริ่มต้นของ "ณ เดือน" ต้องเป็นค่าคงที่ก่อน แล้วค่อยแก้ใน effect
- **`localStorage.getItem()` คืน `null` เมื่อไม่มีค่า และ `Number(null)` เป็น `0`**
  ถ้าเช็คแค่ช่วง 0–11 จะได้ ต.ค. 69 เสมอ ต้องกันกรณี `null` แยกต่างหาก
- **ทุกการเรียก `localStorage` ต้องครอบ try/catch** ตอนนี้เหลือใช้เก็บแค่ค่า "ณ เดือน"
  ข้อมูลผลย้ายไป Supabase หมดแล้ว
- **กราฟแท่งห้ามใช้ SVG + `preserveAspectRatio="none"`** ตัวอักษรไทยจะถูกยืดตามความกว้างจอ
  ใช้ `<div>` + CSS width เป็น % แทน
- **ฟอนต์ไทยห้ามลิงก์ออนไลน์** ใช้สแตก `'Sarabun','Noto Sans Thai','Leelawadee UI',Tahoma`
  (สองตัวหลังติดมากับ Windows)

**ของ Supabase**

- **`NEXT_PUBLIC_*` ถูกฝังตอน build ไม่ใช่ตอนรัน** เพิ่ม env บน Vercel แล้วต้อง Redeploy
  ไม่งั้นค่าจะยังเป็น undefined และเว็บจะเด้งไปหน้า `/setup` ทั้งที่ตั้งค่าไปแล้ว
- **ใน middleware ต้องคืน response ตัวที่ `setAll` เขียนคุกกี้ลงไป** ถ้าคืน
  `NextResponse.next()` ตัวใหม่ token ที่รีเฟรชแล้วจะหาย ผู้ใช้จะหลุดล็อกอินเป็นระยะ
  โดยหาสาเหตุไม่เจอ
- **ใช้ `getUser()` ไม่ใช่ `getSession()` ในการตรวจสิทธิ์** `getSession()` เชื่อคุกกี้ตรง ๆ
  โดยไม่ตรวจกับเซิร์ฟเวอร์
- **สร้าง browser client ครั้งเดียวแล้วใช้ซ้ำ** ถ้าเรียก `createBrowserClient()` ทุก render
  จะมี listener ซ้อนกัน
- **ช่องเบิกจ่ายที่เว้นว่างต้องบันทึกเป็น `null` ไม่ใช่ `0`** ไม่งั้นเดือนที่ไม่ได้กรอก
  จะกลายเป็น "เบิกจ่าย 0 บาท" แล้วกฎแจ้งเตือนจะนับว่ารายงานแล้ว
- **anon key เปิดเผยได้ แต่ service_role key ห้ามเด็ดขาด** อันหลังข้าม RLS ทั้งหมด
- ถ้าเข้าไม่ได้ทั้งที่รหัสถูก ให้เช็คว่าผู้ใช้ถูก **Auto Confirm** แล้วหรือยัง
- **`permission denied for table ...` ไม่ใช่ปัญหา RLS** — เป็นเรื่องสิทธิ์ระดับตาราง (GRANT)
  Postgres ตรวจสิทธิ์ระดับตารางก่อน ถ้าไม่ผ่านจะไม่ไปถึงชั้น RLS เลย
  อาการของ RLS ไม่ผ่านคือ**ได้ผลลัพธ์ว่าง 0 แถว ไม่ใช่ error**
  ปกติ Supabase ตั้ง default privileges ให้ตารางใหม่ในสคีมา public อัตโนมัติ
  แต่บางโปรเจกต์ไม่ได้ตั้งมา จึงต้องมีคำสั่ง `grant` ชัดเจนที่ท้าย `supabase/schema.sql`
  (เจอจริงเมื่อ 28 ส.ค. 2569 หลังสร้างตารางรอบแรก)

**ของ PowerShell (สคริปต์ใน check\)**

- **`$s` กับ `$S` เป็นตัวแปรเดียวกัน** PowerShell ไม่สนตัวพิมพ์เล็กใหญ่
  เคยตั้ง `$s = 0` แล้วทับ string table `$S` จนอ่านข้อมูลผิดทั้งสคริปต์
- **ไฟล์ .ps1 ที่มีภาษาไทยต้องมี BOM** ไม่งั้น PowerShell 5.1 อ่านเป็น ANSI แล้วตัวอักษรเพี้ยน
- **backtick ใน double quote คือตัว escape** เขียน `"``"` ไม่ได้ ต้องใช้ `[char]96`
- ไม่มี `&&` / `||` — ใช้ `A; if ($?) { B }` · ไม่มี ternary, `??`, `?.`
- **อย่า redirect stderr ของ .exe** (`2>$null`) จะกลายเป็น NativeCommandError แม้ exit code = 0
- `-replace` เป็น regex — แทนที่สตริงที่มี `*` `(` `)` ให้ใช้ `.Replace()`

**ของโปรเจกต์เดิม (`Desktop\Gif`) — ยังใช้ได้ถ้าต้องแตก Excel ใหม่**

- **อ่าน sharedStrings.xml ของ .xlsx** ห้ามใช้ `XmlReader.ReadElementContentAsString()`
  เพราะมันเลื่อน reader ข้าม `EndElement` ทำให้ `<si>` ถูกยุบรวมกัน (ได้ 33 จาก 4,354 รายการ)
  ต้องใช้ `XmlDocument` + XPath แทน
- **PowerShell 5.1**: `si` เป็น alias ของ `Set-Item` ห้ามตั้งชื่อฟังก์ชันว่า `SI`
- **แทนที่ marker `/*__PLAN_DATA__*/`** ต้องใช้ `.Replace()` ไม่ใช่ `-replace`
- **JSON ที่ฝังใน `<script>`** ต้องแปลง `<` เป็น `&lt;` กัน `</script>` ในข้อมูลปิดบล็อกก่อนเวลา

## สิ่งที่ยังไม่ได้ทำ

- ยังไม่ได้ดึงชีต **3.4** (รายการครุภัณฑ์/งบลงทุน 426 แถว) เข้ามาแสดง

- ยังไม่มี **รายงานพิมพ์ A4** แบบเว็บเดิม
- **รายการงบประมาณยังกรอกได้เฉพาะระดับโครงการ** ยังไม่ได้ให้กรอกที่ระดับกิจกรรมย่อย
- ยังไม่มีการแนบไฟล์หลักฐานการเบิกจ่าย (Supabase Storage ทำได้ แต่ยังไม่ได้ทำ)
- ยังไม่มีการส่งอีเมล/แจ้งเตือนอัตโนมัติ — ต้องเปิดเว็บดูเอง

  (Supabase มี Realtime ให้อยู่แล้ว เพิ่มทีหลังได้ไม่ยาก)
- **ยังไม่มีระบบสิทธิ์แยกตามหน่วยงาน** ทุกคนที่ล็อกอินแก้ได้ทุกโครงการ
  ถ้าต้องการต้องเพิ่มตาราง `profiles` แล้วแก้เงื่อนไข RLS
- **ยังไม่มีประวัติการแก้ไข** ตารางเก็บแค่ `updated_at` / `updated_by` ของค่าล่าสุด
  ถ้าอยากรู้ว่าใครแก้อะไรเมื่อไหร่ ต้องเพิ่มตาราง audit log

## การแสดงผลบนมือถือ

ทั้งเว็บเป็นตารางเป็นหลัก ซึ่งบนจอโทรศัพท์ถ้าปล่อยให้เลื่อนซ้ายขวาหาคอลัมน์จะใช้แทบไม่ได้
จึงใช้รูปแบบ **stacked table**: แต่ละแถวกลายเป็นการ์ด และเอาหัวตารางมาแปะหน้าค่าแต่ละช่อง

วิธีใช้กับตารางใหม่:

```jsx
<table className="stack">
  <thead>...</thead>          {/* ซ่อนอัตโนมัติบนมือถือ */}
  <tbody>
    <tr>
      <td className="lead">ชื่อรายการ</td>              {/* ช่องแรก ไม่มีป้ายกำกับ ตัวหนา */}
      <td className="num" data-label="งบประมาณ">…</td>  {/* ป้ายกำกับมาจาก data-label */}
      <td className="wide" data-label="ผลผลิต">…</td>   {/* ของกว้าง ขึ้นบรรทัดใหม่ */}
    </tr>
  </tbody>
</table>
```

- `.lead` = ช่องแรก แสดงเป็นหัวการ์ด ตัวหนา ไม่มีป้าย
- `data-label` = ข้อความที่จะแปะหน้าค่าบนมือถือ (ต้องใส่ทุกช่องที่ไม่ใช่ `.lead`)
- `.wide` = ช่องที่มีของกว้าง (ช่องกรอก กราฟแกนต์ ปุ่ม) ป้ายจะขึ้นบรรทัดบนแทนอยู่ข้างหน้า
- ช่องว่าง (`<td />`) ถูกซ่อนอัตโนมัติบนมือถือ

จุดตัดอยู่ที่ **820px** (แท็บเล็ตแนวตั้งลงมา) และมีอีกชั้นที่ **520px** สำหรับจอแคบมาก

เรื่องอื่นที่ปรับให้มือถือ:
- ช่องกรอกใช้ `font-size:15px` บนมือถือ — **ห้ามต่ำกว่านี้** ไม่งั้น iOS จะซูมเข้าเองตอนโฟกัส
- เมนู 7 หน้าเลื่อนแนวนอนแบบ scroll-snap จะได้ไม่ค้างครึ่งหัวข้อ
- แถบหัวเรื่องไม่ sticky บนมือถือ (กินพื้นที่จอ) แต่แถบเมนู sticky แทน
- รายการแจ้งเตือนกับกราฟโดนัทเรียงบนล่างแทนซ้ายขวา
- **ไม่ล็อกการซูม** ในค่า viewport เพราะผู้ใช้ต้องขยายอ่านตัวเลขในตารางได้

ไม่ใช้แถวสลับสี (zebra) เพราะตารางที่กางรายละเอียดได้มีแถวแทรกเข้ามา
ทำให้ลำดับคู่-คี่เลื่อนแล้วลายดูมั่ว ใช้เส้นคั่นกับไฮไลต์ตอนชี้เมาส์แทน

## หน่วยงานรับผิดชอบ — การกรองแบบสายหน่วยงาน

ไฟล์แผนเก็บหน่วยงานเป็นสายคั่นด้วย `/` เช่น `ฝยศ./กนผ./กคพ.` หมายถึงโครงการนี้
เกี่ยวข้องกับทั้ง ฝยศ. กนผ. และ กคพ. (ระดับโครงการมีค่าต่างกัน 72 แบบ)

**ดรอปดาวน์แสดงเฉพาะ "หน่วยงานตัวหน้า"** คือหน่วยที่เคยขึ้นต้นสายอย่างน้อยหนึ่งครั้ง
แต่**การกรองจับทุกตำแหน่งในสาย**:

- เลือก `ฝยศ.` → ได้ `ฝยศ./กนผ./กคพ.` `ฝยศ./กบค.` `ฝยศ./กปม.` ครบ
- โครงการ `สวย./ฝทม.` โผล่ทั้งตอนเลือก `สวย.` และตอนเลือก `ฝทม.`

**ข้อมูลต้นฉบับพิมพ์ไม่สม่ำเสมอ** — มีทั้ง `ฝพก.` กับ `ฝพก`, `สวย.` กับ `สวย`,
`กผฐ.` กับ `กผฐ` และมีเว้นวรรคหลัง `/` (`ฝสผ./ กยท.ข.`)
`normUnit()` ใน `lib/rollup.js` จึงตัดช่องว่างและจุดท้ายออกก่อนเทียบเสมอ
**ถ้าไม่ normalize จะกลายเป็นคนละหน่วยงานแล้วยอดกระจัดกระจาย**

⚠️ **โครงการหนึ่งอยู่ได้หลายหน่วยงาน ผลรวมของทุกหน่วยงานจึงมากกว่ายอดจริงของทั้งแผน**
ตารางสรุปตามหน่วยงานในหน้างบประมาณใช้ดูภาระของแต่ละหน่วย ไม่ใช่ใช้บวกหายอดรวม
(มีข้อความเตือนอยู่ใต้หัวข้อในหน้าเว็บแล้ว)

## เรียกรายงานเป็น PDF

มีสองแบบ ใช้กลไกเดียวกันคือ `window.print()` แล้วผู้ใช้เลือก "Save as PDF"
**ไม่ใช้ไลบรารี PDF** เพราะเครื่องที่พัฒนาไม่มี Node.js และวิธีนี้ได้ฟอนต์ไทยถูกต้องเสมอ

| แบบ | คลาสที่ body | ใช้ที่ไหน |
|---|---|---|
| รายงานงบรายโครงการ | `printing-report` | ปุ่ม PDF ที่แถวโครงการ — สร้าง DOM รายงานแยกใน `budget-report.jsx` |
| รายงานหน้าปัจจุบัน | `printing-page` | ปุ่ม "ดาวน์โหลด PDF" ที่มีทุกหน้า (`components/print-button.jsx`) |

แบบที่สองพิมพ์สิ่งที่ผู้ใช้เห็นอยู่ตอนนั้น (ผ่านตัวกรองที่เลือกไว้แล้ว) โดยซ่อนเมนู
ตัวกรอง และปุ่มทิ้ง แล้วสร้างหัวกระดาษจาก `data-print-title` / `data-print-sub` ที่ body

รายละเอียดที่ต้องรู้:
- **เบราว์เซอร์ตั้งชื่อไฟล์ PDF จาก `document.title`** `PrintButton` จึงเปลี่ยนชื่อชั่วคราว
  ก่อนพิมพ์แล้วคืนค่าเดิม ผู้ใช้จะได้ไฟล์ที่ชื่อสื่อความหมาย ไม่ใช่ชื่อเดียวกันหมด
- หัวกระดาษต้องอยู่ใน `body::before` ตัวเดียวแล้วขึ้นบรรทัดด้วย `\A` + `white-space:pre-line`
  **ถ้าแยกบรรทัดที่สองไปใส่ `::after` มันจะไปโผล่ท้ายเอกสาร** ไม่ใช่ใต้หัวเรื่อง
- ตารางแบบ `stack` ตอนพิมพ์ถูกสั่งให้กลับเป็นตารางปกติ เพราะกระดาษ A4 กว้างพอ
- ช่องกรอกตอนพิมพ์ถอดกรอบและพื้นหลังออก เหลือแต่ค่า

## แบ่งโครงการตามกลยุทธ์

หน้าโครงการ: เมื่อเลือกยุทธศาสตร์ ตารางจะแทรกแถวหัวกลุ่มคั่นตามกลยุทธ์
พร้อมจำนวนรายการและยอดงบของกลุ่มนั้น ถ้าไม่เลือกยุทธศาสตร์จะแสดงรวดเดียวเหมือนเดิม
เพราะข้ามยุทธศาสตร์แล้วกลุ่มจะเยอะเกินอ่าน

การวาดแถวถูกแยกเป็นฟังก์ชัน `renderRow()` เพื่อให้เรียกได้ทั้งแบบแบนและแบบแบ่งกลุ่ม
(เป็น function declaration จึงถูก hoist ให้ JSX ด้านบนเรียกได้)

## รายงานผลรายเดือนในลิ้นชัก (components/report-tab.jsx)

**รายงานหลักอยู่ที่ระดับโครงการเสมอ** กิจกรรมเป็นบล็อกเพิ่มด้านล่าง ไม่ใช่ตัวแทน
เรียงตามนี้:

1. งบประมาณของโครงการ — จัดสรร / ใช้ไป / คงเหลือ (อ่านอย่างเดียว)
2. สถานะ + ความก้าวหน้า
3. **ตัวชี้วัดผลผลิต** ค่าตามแผน + ช่องรายงานผล + ช่องปัญหาอุปสรรค
4. **ตัวชี้วัดผลลัพธ์** ค่าตามแผน + ช่องรายงานผล + ช่องปัญหาอุปสรรค
5. ตารางรายงานผลรายเดือน 12 เดือน (ผลผลิต / ผลลัพธ์ / ปัญหา / วิธีแก้)
6. ถ้ามีกิจกรรมย่อย — เลือกกิจกรรม แล้วเห็นงบของกิจกรรมนั้น
   พร้อมตัวชี้วัดผลผลิต + ช่องรายงานผล + ปัญหาอุปสรรค

ช่องรายงานผลกับปัญหาอุปสรรคของตัวชี้วัดเก็บที่ `project_results`
(`output_result` `output_issue` `outcome_result` `outcome_issue`) **ไม่ใช่** `monthly_reports`
เพราะเป็นสรุปทั้งปี 1 ชุดต่อรายการ ไม่ใช่ค่ารายเดือน

**กิจกรรมไม่มีช่องผลลัพธ์** เพราะผลลัพธ์ (Outcome) เป็นตัวชี้วัดของทั้งโครงการ
ไม่ได้วัดรายกิจกรรม ถ้าเปิดให้กรอกจะได้ค่าที่รวมกันไม่ได้

**ไม่มีช่องกรอกงบประมาณในลิ้นชักอีกแล้ว** — งบบันทึกที่หน้า "งบประมาณโครงการ" ที่เดียว
ลิ้นชักกับตารางโครงการดึงยอดมาแสดงอย่างเดียว (ได้รับจัดสรร / ใช้ไป / คงเหลือ)
เพื่อไม่ให้มีสองแหล่งที่กรอกเงินแล้วตัวเลขขัดกัน

มีปุ่ม **บันทึกรายงาน** (เรียก `saveNow()`) ทั้งที่ระบบบันทึกอัตโนมัติอยู่แล้ว
เพราะผู้ใช้ต้องการเห็นการยืนยันว่าข้อมูลขึ้นครบจริง

ปุ่ม **PDF** ในหัวลิ้นชักใช้โหมด `body.printing-drawer` ซึ่งซ่อนหน้าเบื้องหลังทิ้ง
แล้วคลี่ลิ้นชักจากแผงลอยด้านข้างให้เป็นเอกสารที่ไหลลงกระดาษได้
(ต่างจาก `printing-page` ที่พิมพ์ทั้งหน้า และ `printing-report` ที่พิมพ์รายงานงบรายโครงการ)

## SQL ที่ต้องรันใน Supabase (สรุปรวม)

ไฟล์ `supabase/schema.sql` **รันทั้งไฟล์ซ้ำได้เสมอ ข้อมูลเดิมไม่หาย**
ถ้าไม่แน่ใจว่ารันอะไรไปแล้วบ้าง ให้วางทั้งไฟล์แล้ว Run ทีเดียวจบ

| 28 ส.ค. | 3 ตารางแรก + RLS | ทั้งเว็บ |
| 28 ส.ค. | `budget_entries`, `risk_reports` | งบประมาณโครงการ, ความเสี่ยงรายเดือน |
| 28 ส.ค. | `grant` ระดับตาราง | ทั้งเว็บ (แก้ permission denied) |

| 1 ก.ย. | `monthly_reports.issue` / `solution` | ปัญหาอุปสรรค/วิธีแก้ รายเดือน |

พร้อมขึ้นข้อความบอกว่าต้องรันอะไร

## ผู้ช่วย AI (Gemini)

หุ่นยนต์การ์ตูนลอยมุมขวาล่างทุกหน้า (`components/assistant.jsx` mount ใน `shell.jsx` ต่อจาก `</main>`)
ถามได้ทั้ง "กรอกงบตรงไหน" และ "ตอนนี้มีโครงการวิกฤตกี่โครงการ"
ประวัติการสนทนาอยู่ใน state เท่านั้น **ปิดหน้าแล้วหาย** ตามที่ผู้ใช้เลือก

### คีย์อยู่ฝั่งเซิร์ฟเวอร์ที่เดียว

`app/api/chat/route.js` อ่าน `process.env.GEMINI_API_KEY` แล้วยิง REST ของ Gemini
ด้วย `fetch` ตรง ๆ ไม่ลง SDK (เครื่องที่พัฒนาไม่มี Node.js จึงติดตั้งอะไรไม่ได้)

⚠️ **ห้ามตั้งชื่อ env เป็น `NEXT_PUBLIC_GEMINI_API_KEY`** ตัวแปรที่ขึ้นต้นด้วย
`NEXT_PUBLIC_` ถูกฝังลงในบันเดิลที่ส่งให้เบราว์เซอร์ ใครเปิด devtools ก็อ่านคีย์ได้

`GET /api/chat` คืน `{ configured }` — ไม่ตั้งคีย์ = ปุ่มแชทไม่แสดงเลย
เว็บที่เหลือทำงานปกติ (แนวเดียวกับที่ฟีเจอร์อื่นซ่อนตัวเมื่อฐานข้อมูลยังไม่พร้อม)
เปลี่ยนรุ่นโมเดลได้ด้วย `GEMINI_MODEL` ค่าเริ่มต้น `gemini-3.6-flash`

`middleware.js` เพิ่มเงื่อนไข: `/api/*` ที่ยังไม่ล็อกอินต้องได้ **401 เป็น JSON**
ไม่ใช่ redirect ไป `/login` ไม่งั้น `fetch` จะได้ HTML ของหน้า login กลับมา
แล้ว `res.json()` พังโดยไม่บอกสาเหตุ

### ข้อมูลที่ส่งไปกับคำถาม

`lib/assistant-context.js` ประกอบสรุปฝั่งเบราว์เซอร์ (ข้อมูลโหลดมาอยู่แล้ว
เซิร์ฟเวอร์จึงไม่ต้องไปอ่าน Supabase ซ้ำ) แล้วแนบไปกับ **คำถามล่าสุดเท่านั้น**
ไม่แนบซ้ำทุกข้อความ เพราะเป็นชุดเดียวกันและกินโควตาเปล่า ๆ

**ห้ามส่ง `data/plan-data.json` ทั้งก้อน (404 KB)** ส่งเฉพาะ:
สรุปการแจ้งเตือน · แจ้งเตือนสำคัญ 15 รายการแรก · งบรวม/รายเดือน/รายหมวด ·
สรุปตามหน่วยงาน/ยุทธศาสตร์/แหล่งเงิน/แผนงาน · ตัวชี้วัด 13 ตัว ·
และ **โครงการที่เกี่ยวกับคำถามไม่เกิน 8 รายการ** พร้อมรายละเอียดเต็ม

หาโครงการที่เกี่ยวข้องสามชั้น: รหัส 6-9 หลักในคำถาม → ชื่อหน่วยงานใน `ORG_UNITS`
→ ชิ้นส่วนคำยาว ≥ 4 ตัวอักษรที่ตรงกับชื่อโครงการ
ภาษาไทยไม่เว้นวรรคระหว่างคำ การตัดคำให้ถูกต้องต้องมี dictionary ซึ่งเกินจำเป็น
จึงจับชิ้นส่วนคำยาว ๆ แทน ถ้าไม่เจอเลยก็ยังส่งสรุปภาพรวมไป
แล้วบอกบอทให้ขอชื่อหรือรหัสโครงการเพิ่ม

ทุกยอดเรียกฟังก์ชันเดิม (`buildAlerts` `summarize` `budgetRollup` `entriesByCost`
`achievement` `riskLevelInfo`) **ไม่เขียนตรรกะรวมยอดซ้ำ** ถ้าเขียนใหม่ ตัวเลขที่บอทตอบ
จะค่อย ๆ เพี้ยนไปจากที่หน้าเว็บแสดงโดยไม่มีใครสังเกต

### `lib/assistant-prompt.js` ห้าม import `lib/store.jsx`

`store.jsx` เป็น `"use client"` ส่วน route handler คอมไพล์ในชั้น react-server
ถ้า import เข้ามาจะได้ client reference proxy แทนค่าจริง แล้วพังตอนเรียกใช้
ชื่อ 4 หมวดค่าใช้จ่ายจึงพิมพ์ไว้ในไฟล์พรอมป์ตเอง (ต้องแก้ให้ตรงกับ `COST_FIELDS` ถ้ามีการเปลี่ยน)

ส่วน `RULES` `KIND_LABEL` `MONTHS` เป็นโมดูลธรรมดา จึงดึงมาประกอบข้อความได้
**เกณฑ์แจ้งเตือน 8 ข้อในพรอมป์ตจึงมาจากค่าจริงเสมอ** ปรับ `RULES` แล้วบอทเปลี่ยนตาม
ไม่ต้องแก้สองที่แล้วลืมที่หนึ่ง


### เพดานคำตอบกับการ "คิด" ของโมเดล

รุ่น 2.5 ขึ้นไป **คิดก่อนตอบ และการคิดกิน `maxOutputTokens` ด้วย**
ตอนแรกตั้งไว้ 1200 คำตอบจึงถูกตัดกลางประโยคทั้งที่เขียนยังไม่จบ แก้สองทาง:

1. ส่ง `generationConfig.thinkingConfig.thinkingBudget = 0` ปิดการคิด
   คำถามในเว็บนี้เป็นการอ่านตัวเลขจาก context ที่ส่งไปให้แล้ว ไม่ต้องใช้การคิดยาว
   ถ้ารุ่นไหนปิดไม่ได้แล้วตอบ 400 ระบบจะ **ลองใหม่แบบไม่ส่ง `thinkingConfig`** ให้เอง
   แล้ว**จำไว้ว่ารุ่นนี้ไม่รับ** จะได้ไม่เสียคำขอทิ้งทุกครั้ง (Gemini 3 ไม่รับ)
   เงื่อนไขลองใหม่ดูแค่สถานะ 400 ไม่ดูข้อความ เพราะ Gemini 3 ตอบแค่
   "Request contains an invalid argument." ไม่บอกว่าฟิลด์ไหนผิด
   ดีกว่าเดาล่วงหน้าว่ารุ่นไหนรองรับ เพราะ Google เปลี่ยนรุ่นอยู่เรื่อย ๆ
2. ขยายเพดานเป็น 8192 เผื่อรุ่นที่ปิดการคิดไม่ได้

ถ้ายังชนเพดานอีก route จะส่ง `truncated: true` กลับมา แล้วแผงแชทขึ้นหมายเหตุ
ว่าคำตอบถูกตัด **ไม่ปล่อยให้ผู้ใช้เข้าใจว่านั่นคือคำตอบทั้งหมด**
และพรอมป์ตสั่งให้ตอบจบในคำตอบเดียว รายการเกิน 10 ให้แสดง 10 อันดับแรกแล้วบอกว่ามีอีกกี่รายการ


### หุ่นยนต์ผู้ช่วย

ปุ่มลอยเป็นหุ่นยนต์การ์ตูน **วาดเป็น SVG ในโค้ด** (`Robot` ใน `components/assistant.jsx`)
ไม่ใช้ไฟล์รูปเพราะต้องมีสองชุดสำหรับโหมดสว่าง/มืด และไม่ใช้ไลบรารีไอคอน
เพราะเครื่องที่พัฒนาลง dependency ไม่ได้

สีอิง `currentColor` กับตัวแปรธีมทั้งหมด จึงสลับโหมดมืดได้เอง
บนปุ่มพื้นเขียวเข้มต้องกลับเป็นสีอ่อน (`.chatfab .robot`) ไม่งั้นหุ่นจะจมไปกับพื้น
— ปัญหาเดียวกับตราสัญลักษณ์ในแถบหัวเรื่องที่ต้องรองด้วยวงกลมขาว

หุ่นโผล่ 4 จุด: บนปุ่มลอย · หัวแผงแชท · หน้าจอต้อนรับตอนยังไม่มีบทสนทนา ·
ข้างคำตอบทุกข้อความ (`.chatavatar` ใน `.chatrow`) จะได้แยกออกทันทีว่าอันไหนบอทพูด

**คำทักทาย "ให้ช่วยอะไรไหมครับ"** เด้งเป็นบอลลูนข้างปุ่มหลังโหลดหน้า 1.2 วินาที
ไม่เด้งพร้อมหน้าจนบังของที่ผู้ใช้กำลังอ่าน กดปิดหรือเปิดแชทแล้ว
จำไว้ใน `localStorage` (`raot-chat-greeted`) ไม่ทักซ้ำอีก
ทักทุกครั้งที่เปิดเว็บจะกลายเป็นน่ารำคาญ แต่ข้อความเดียวกันยังอยู่ในหน้าจอต้อนรับเสมอ

แอนิเมชันมีสามอย่าง: ไฟเสาอากาศกะพริบ · ตากะพริบทุก 5.5 วินาที ·
หุ่นกระเด้งตอนกำลังคิด ทั้งหมดถูกปิดเมื่อเครื่องตั้ง `prefers-reduced-motion: reduce`

`.chatdock` (ตัวห่อปุ่ม + บอลลูน) ถูกเพิ่มเข้าไปในรายการที่ซ่อนตอนพิมพ์ด้วย
ไม่งั้นบอลลูนทักทายจะติดไปในไฟล์ PDF

### markdown ในคำตอบ

บอทตอบมาเป็น markdown ตามธรรมชาติ ถ้าแสดงดิบ ๆ จะเห็นดอกจันปนอยู่
`components/assistant.jsx` จึงมีตัวแปลงย่อ ๆ รองรับ **ตัวหนา** · รายการ (`*` `-` `•`) · หัวข้อ (`#`)
ไม่ลงไลบรารี markdown ทั้งตัวเพื่อสามรูปแบบนี้ (และเครื่องที่พัฒนาลงอะไรไม่ได้อยู่แล้ว)

### ข้อควรรู้

- context ประกอบฝั่ง client ผู้ใช้แก้ค่าที่ส่งได้ในทางทฤษฎี แต่กระทบแค่คำตอบของตัวเอง
  และเขาเห็นข้อมูลชุดนั้นในหน้าเว็บอยู่แล้ว จึงไม่ใช่ช่องโหว่
- เพดานฝั่งเซิร์ฟเวอร์ (ไม่เชื่อ client): ข้อความละ ≤ 2000 ตัวอักษร ·
  ประวัติ ≤ 12 ข้อความ · context JSON ≤ 60 KB
- คีย์ฟรีมีลิมิตต่อนาที เจอ 429 = โควตาเต็ม ให้รอแล้วถามใหม่ (แปลเป็นข้อความไทยแล้ว)
- `.chatfab` กับ `.chatpanel` ถูกซ่อนใน `@media print` **ทุกโหมด** ไม่ใช่เฉพาะโหมดใดโหมดหนึ่ง
  ไม่งั้นปุ่มแชทจะติดไปในไฟล์ PDF
- แผงเต็มจอเมื่อ ≤ 820px ช่องพิมพ์ `font-size:15px` กัน iOS ซูมเข้าอัตโนมัติ (กับดักเดิม)
- **คำตอบของ AI ไม่ใช่ข้อมูลทางการ** เขียนกำกับไว้ท้ายแผงแชทแล้ว
- **รอบนี้ไม่ต้องรัน SQL** ไม่แตะฐานข้อมูล
